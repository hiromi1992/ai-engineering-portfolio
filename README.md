## 現在の主力開発

### [Signal Harvester / ICP](projects/02_signal_harvester.md)

**WebやGitHub等から得た情報を、出典・時点・反証・不確実性・履歴を失わずに後続のAIや分析へ渡す情報基盤です。**

複数の収集処理を独立して動かし、1回の実行ごとに追記型で記録します。各観測候補には、情報源、発生時刻と観測時刻、支持材料、反証、未知事項、新規・更新・重複関係などを持たせます。

ICPで集めた情報をそのまま確定事実にはせず、検証済みのものだけをSignal Harvester側の正式な観測・根拠・シグナルへ昇格する責任分界にしています。

**現在の状態：非公開の開発リポジトリで主要機能を実装・検証済み。観測範囲を拡張中。**

### [AI開発基盤 / Review-Handoff Platform](projects/01_ai_development_foundation.md)

**AIへ実装を任せた後、AI自身の完了報告ではなく、Git・テスト・実際の変更内容から受入可否を判断する共通基盤です。**

成功・失敗だけでなく「結果不明」を独立した状態として扱い、確認前の再実行を止めます。重要な変更では、自動テストの後に独立レビューを追加し、必要なら実装だけでなく設計・要件まで戻します。

**現在の状態：非公開の開発リポジトリで主要機能を実装・検証済み。安全条件を確認できない自動実行は制限。**

## 共通して重視している設計

プロジェクトごとに用途は異なりますが、共通して次を重視しています。

- **AIの自己申告を完了証拠にしない**
- **元データとAIによる解釈を分ける**
- **支持材料だけでなく反証・不確実性・未知事項も残す**
- **「0件」と「見ていない」を区別する**
- **出来事の発生時刻と、システムが知った時刻を分ける**
- **重要な変更は独立して再検証する**
- **外部操作では「結果不明」を持ち、確認前の再実行を防ぐ**
- **評価データを結果に合わせて変えない**

→ [AIシステム設計で重視していること](principles/ai_system_design.md)

## このポートフォリオで見てほしいこと

- **課題を構造化して要件へ落とす**：曖昧な目的を、実装可能な要件・状態・データ構造・受入条件へ整理する
- **AIへ実装を委譲する**：AIへ直接実装を任せつつ、対象範囲や完了条件は自分で定義する
- **結果を独立して確認する**：AIや自動テストの成功だけで終わらせず、実状態まで確認する
- **失敗を設計へ戻す**：不具合を個別修正で終わらせず、状態設計・確認ルール・回帰テストへ反映する
- **後から判断を再現できるようにする**：出典、時点、根拠、反証、評価条件、変更履歴を残す

詳しい対応関係は [経験領域とプロジェクト対応](capabilities/README.md) にまとめています。
