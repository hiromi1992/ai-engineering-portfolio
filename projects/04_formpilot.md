# FormPilot

**Webフォーム自動化に向け、二重実行や誤送信を防ぐ状態管理・復旧基盤を持つWindowsアプリです。**

**現在の状態：非公開の開発リポジトリで状態管理、処理キュー、認証、観測基盤を実装・検証済み。自動実行を段階的に検証中で、実フォーム送信は未実装です。**

## 何を作っているか

Webフォーム業務の自動化に向けたWindowsデスクトップアプリです。

外部へ送信する処理は、失敗時に二重送信などの影響が出ます。そのため、送信機能を先に作るのではなく、**処理状態、失敗理由、再試行可否、復旧方法を確認できる基盤**から整備しています。

## 内部構成

```text
画面
 ↓
制限した画面・内部処理間の橋渡し
 ↓
実行管理
├─ 処理キュー
├─ 状態遷移
├─ 再試行判定
├─ 実行履歴
└─ 失敗理由の記録
 ↓
保存層
├─ SQLite：端末側の処理対象・設定
└─ PostgreSQL：作業領域・認証・権限
 ↓
外部フォーム操作
```

外部フォーム操作を追加する前に、**その操作が開始前なのか、実行中なのか、送信された可能性があるのか、完了したのか**を内部で区別できる状態にしています。

## 状態と再試行

```text
未開始
  ↓
実行中
  ├─ 完了
  ├─ 明確な失敗
  │     ↓
  │   再試行可能か判定
  │
  └─ 送信された可能性あり
          ↓
        自動再試行を停止
          ↓
        実状態または人の確認
```

特に、通信切断などで結果が確認できない場合に、単純に「失敗」とみなして再送しないことを重視しています。

外部システム側では処理が完了している可能性があるため、**結果不明の状態を持つことで二重実行を防ぐ**設計です。

## 実装済みの主な基盤

- Electron + Reactによるデスクトップ構成
- 画面から内部機能へアクセスできる範囲を制限したIPC Bridge
- SQLiteでのCampaign / Target保存とMigration
- 中断から復旧できる処理キュー
- PostgreSQLを使ったWorkspace認証・Role管理
- Sender / Template / Schedule / Pacing / Test mode設定
- 実行イベントと失敗理由の記録
- 型確認、静的検査、単体テスト、ビルド、デスクトップ動作確認

## 主な設計

- 「まだ開始していない」「実行中」「送信した可能性がある」「完了」を分けて扱う
- 送信した可能性がある場合は、自動で同じ処理を繰り返さない
- 再試行してよい失敗と、人の確認が必要な失敗を分ける
- 状態遷移と実行履歴を残し、復旧時に前回の状態を確認できるようにする
- 画面から内部処理へ無制限にアクセスできないよう境界を設ける
- 外部操作を追加する前に、状態と失敗理由を観測できるようにする

## なぜこの順番で作っているか

フォーム送信そのものを先に自動化すると、成功時の動作は確認できても、通信切断・途中終了・再起動・二重送信などの異常系で安全に復旧できません。

そのため、

**観測できる → 状態を区別できる → 復旧できる → その後に外部操作を広げる**

という順番で実装しています。
