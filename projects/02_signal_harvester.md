# Signal Harvester / ICP

**現在の状態:** 情報収集・履歴・再検証・根拠管理の主要機能は **実装済み**  
**外部観測:** 対象Source・取得方法を段階的に拡張中

## 概要

GitHub / Hacker News / RSS / Webなどから情報を取得し、**出典・取得時点・履歴・変更内容を保持したまま、後続の分析やAI処理へ渡す**ための情報基盤です。

単に情報を集めるだけでなく、

> 「何を・いつ・どこから・どの方法で取得し、その後どう変化したか」

を後から再検証できることを重視しています。

## 対象とした課題

AI分析や意思決定へ利用する場合、単純な情報収集だけでは不十分です。

- 同一情報の転載・再取得を別々の根拠として数えてしまう
- Web更新後に、当時取得した内容を再現できない
- AIが利用した引用が元本文のどこに存在したか追跡できない
- 「情報源」と「取得方法」を混同しやすい
- 過去の評価を再実行した際に、その後の更新情報が混入する

## 主な設計判断

### 1. 取得結果と取得条件を保存する
本文・ハッシュ値・取得時刻・情報源・取得方法等を分けて保存します。

### 2. 過去の再検証では現在のWebへ再取得しない
過去の実行結果を検証する際は保存済みデータを使い、その後の更新内容が混ざらないようにします。

### 3. 情報源と取得方法を分離する
「何の情報か」と「どの方法で取得したか」を別々に管理し、取得手段が変わっても情報源の識別を維持します。

### 4. 条件を満たさない外部取得は実行しない
外部取得を拡張する際も、承認・利用条件・取得条件等を確認できない場合は実行しない設計としています。
