# Signal Harvester / ICP

**Web情報を、出典・取得時点・履歴を失わずにAIや分析へ渡す情報基盤です。**

**現在の状態：非公開の開発リポジトリで情報収集、履歴保存、再検証、出典管理の主要機能を実装・検証済み。観測する情報源を拡張中です。**

## 何を作っているか

GitHub / Hacker News / RSS / Webなどから情報を取得し、**出典、取得時点、履歴、変更内容を残したまま後続の分析やAI処理へ渡す**ための情報基盤です。

情報を集めるだけでなく、「いつ、どこから、どう取得した情報か」「後から内容が変わっていないか」を確認できる状態にすることを重視しています。

## 解きたい問題

- 同じ情報の転載や再取得を、別々の根拠として数えてしまう
- Webが更新された後、当時取得した内容を再現できない
- AIが使った引用が元本文のどこにあったか追えない
- 過去の評価を再実行したとき、その後の更新情報が混ざる
- 「見つからなかった」と「存在しない」を混同してしまう
- AIが重要と判断した情報を、そのまま確定事実として扱ってしまう

## 内部構成

ICPでは、用途の異なる複数の収集処理を独立して動かしています。現在は主に、**全体動向、コンピュータビジョン、AI技術、過去事例**の4系統です。

各収集処理の結果は、既存データを上書きするのではなく、**1回の実行ごとに新しい実行記録として追記**します。

```text
外部情報源
    ↓
複数の収集処理
    ↓
実行記録
    ├─ 実行日時
    ├─ 適用した方針・指示の版
    ├─ どこまで探索できたか
    ├─ 観測候補
    └─ 欠測・未確認領域
    ↓
観測候補
    ├─ 支持する根拠
    ├─ 反証・限定材料
    ├─ 不確実性
    ├─ 次に確認すべき根拠
    ├─ まだ分からないこと
    └─ 既存情報との新規・更新・重複関係
    ↓
検証・昇格
    ↓
Signal Harvester
```

ICPに保存された時点では、データは**確定事実ではなく候補情報**として扱います。検証を通過した情報だけを、Signal Harvester側の正式な観測・根拠・出所・シグナルとして扱う責任分界にしています。

## データ構造

### 1. 実行単位

1回の収集について、次のような情報をまとめて保存します。

- どの収集処理を実行したか
- 実行開始・終了時刻
- 適用した指示や方針の版
- 探索した範囲と、探索できなかった範囲
- 保存した観測候補
- 欠測や未確認事項
- 保存結果を実際に読み戻して確認できたか

この単位を追記型で残すことで、後から「その時点で何を探索し、何を知っていたか」を再現できるようにしています。

### 2. 観測候補

1件の情報は本文だけではなく、次のような属性を分けて持ちます。

- 安定した識別子
- 元情報への参照
- テーマ、企業・技術、地域などの関連情報
- 情報源の種類と独立性
- **出来事が発生・公開された時刻**
- **システムがその情報を観測した時刻**
- 既存情報に対する新規・更新・重複関係
- 情報源が実際に主張している内容
- 反証や主張を限定する材料
- 不確実性
- 次に確認すべき根拠
- まだ分からないこと
- 同じ出来事・テーマに属する他情報との関係

特に、**世界でいつ起きたか**と**システムがいつ知ったか**を分けています。これにより、過去時点の判断を再現するときに、後から得た情報を混ぜないようにできます。

### 3. 根拠と関係

同じ発表が複数サイトへ転載されても、それを複数の独立した根拠として数えないようにしています。

情報源、元記事、内容、既存の識別子などを使い、新規・更新・重複を区別します。また、意味が似ているという理由だけで既存データを破壊的に統合せず、元の出所と関係性を残します。

### 4. 欠測も状態として保存

「情報がなかった」だけで終わらせず、少なくとも次の違いを残す設計にしています。

- 実際に観測して0件だった
- その情報源を見に行けなかった
- 情報源が利用できなかった
- 情報源自体が有効化されていなかった
- 探索上限に達した
- 優先順位の都合で今回は探索しなかった

これにより、**観測できなかったことを、存在しないこととして扱わない**ようにしています。

## ICPとSignal Harvesterの責任分界

```text
ICP
情報を収集・正規化・重複確認
        ↓
候補情報として保存
        ↓
出所・時刻・根拠・反証・訂正履歴を保持したまま検証
        ↓
Signal Harvester
正式な観測・根拠・出所・シグナルとして管理
```

ICPの役割は、候補情報を安全に集め、後から再検証できる状態で残すところまでです。Signal Harvesterへの昇格時には、元情報の識別子、時刻、根拠、出所、訂正履歴、他情報との関係を保持します。

## 主な設計

- 本文、ハッシュ値、取得時刻、情報源、取得方法を分けて保存する
- 過去の結果を再検証するときは、保存済みデータを使い、現在のWebを取り直さない
- 情報源そのものと、RSS・Web取得などの取得手段を分けて管理する
- 外部取得の条件を確認できない場合は実行しない
- 原本は追記型で保持し、分析時に必要な形へ変換する
- AIによる解釈と、元情報から確認できる事実を分ける
- 支持材料だけでなく、反証・不確実性・未知事項も残す
